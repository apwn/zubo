Skill Development

Skills are self-contained TypeScript modules that extend Zubo's capabilities. Each skill lives in its own directory under ~/.zubo/skills/ and consists of two files: SKILL.md (definition) and handler.ts (implementation).

Quick Start

# Scaffold a new skill
zubo skills new

# This creates:
# ~/.zubo/skills/my-skill/
#   SKILL.md      — Skill definition
#   handler.ts    — Implementation

SKILL.md Format

The SKILL.md file declares your skill's metadata and input schema using Markdown:

# weather

Get current weather and forecasts for any location.

## Input
```json
{
  "location": { "type": "string", "required": true, "description": "City name or coordinates" },
  "units": { "type": "string", "default": "metric", "description": "metric or imperial" }
}
```

## Secrets
- `OPENWEATHER_API_KEY` — Required for the OpenWeather API

## Tags
weather, api, utility

Sections

SectionRequiredDescription
# nameYesSkill name (H1 heading)
DescriptionYesText after the heading, before any H2
## InputYesJSON schema for tool input parameters
## SecretsNoList of required secrets
## TagsNoComma-separated tags for registry search

handler.ts Pattern

The handler exports a default async function:

import type { SkillInput, SkillResult } from "zubo/types";

export default async function handler(input: SkillInput): Promise<SkillResult> {
  const { location, units = "metric" } = input.params;
  const apiKey = input.secrets.OPENWEATHER_API_KEY;

  if (!apiKey) {
    return { error: "OPENWEATHER_API_KEY not set" };
  }

  const url = `https://api.openweathermap.org/data/2.5/weather?q=${encodeURIComponent(location)}&units=${units}&appid=${apiKey}`;
  const res = await fetch(url);
  const data = await res.json();

  return {
    result: `${data.name}: ${data.main.temp}°, ${data.weather[0].description}`,
    data: data,
  };
}

SkillInput

FieldTypeDescription
paramsRecord<string, any>Parsed input parameters from the LLM
secretsRecord<string, string>Decrypted secrets the skill declared

SkillResult

FieldTypeDescription
resultstringHuman-readable result text
dataanyOptional structured data
errorstringError message (if failed)

Sandbox Behavior

User-installed skills run in isolated subprocesses by default. This provides:

  • Memory isolation — skills cannot access the parent process memory
  • Timeout enforcement — skills are killed after sandbox.timeoutMs (default: 30s)
  • Controlled access — skills only receive declared secrets

To disable sandboxing (not recommended), set sandbox.enabled: false in config.json.

Secrets Access

Skills only receive the secrets they declare in SKILL.md. Users set secrets via chat:

"Set my OPENWEATHER_API_KEY to abc123..."

Testing

Test your skill by asking Zubo to use it:

"What's the weather in Tokyo?"

Zubo's agent will automatically match the request to your skill based on its description and input schema. Check the dashboard logs for execution details.

Publishing

Share your skill with the community:

# Validate and publish
zubo publish

This submits your skill to the Zubo skill registry. Others can install it with:

zubo install weather
